Python 脚本

普通 Python：ctx 为接口，inputs 为输入，variables 为脚本变量，result 为返回值。代码以当前用户权限运行，可导入本机 Python 标准库；只运行你信任的代码。

可用接口：ctx.control(字段, 值)、ctx.refresh()、ctx.wait(秒)、ctx.log(内容)、ctx.http(连接名称, 路径)、ctx.request(连接名称, 方法, JSON请求体, 路径)、ctx.mqtt(连接名称, 路径)、ctx.calendar(连接名称, 小时, 关键字)、ctx.now()、ctx.events(起始序号, 字段, 来源)。运行上限受脚本时限约束；单个自定义模块最长 3600 秒。

怎样选择接口？

HTTP / 传感器：接口需要返回 JSON，例如 {"temperature":26.5}。积木中填写路径 temperature；嵌套字段用 sensor.value，数组可用 items.0.value。

MQTT：填写已有 broker、主题、端口与凭据。读取积木订阅并等待下一条或 retained JSON 消息，不会自动发现硬件。

日历：填写自己的 HTTPS ICS 订阅地址，支持重复事件和全天事件。它不是 Google/微软账号 OAuth 登录。

网络与时间：网络探测使用所选 HTTP 连接的 HEAD 请求；联网时间读取 HTTP Date 头。星期和本地时间直接使用所选时区，无需联网。

第一次使用：三步完成

1. 连接自己的房间

打开“连接向导”，粘贴设备编号或选择二维码照片。官方 App 必须已登录并绑定同一房间；二维码不是账号密码。

2. 获取一次授权

按向导准备电脑，配置防火墙，在手机安装 WireGuard 并扫码。安装并信任 mitmproxy 证书后刷新官方 App。身份核对成功会自动进入面板。

3. 控制和自动化

面板可以开关空调、控制摆风。新建一个脚本，命名后拖入：开机 → 等待 → 关机。拖动积木改变顺序，点击数字修改时间。

动作积木上下拼接，按顺序执行；圆角输入槽接数字、文字或数据。

如果放入比较条件，再把动作放进分支。条件不成立可以走“否则”。

循环把动作放在内部。持续循环必须加停顿，避免不断请求接口。

变量给数据起名字，例如“变量名”。先“设置变量”，再用“读取变量”。

错误处理主分支失败后执行错误分支。外部传感器失联时建议记录提示，不要假装读到正常温度。

试运行不发真实控制和消息，外部数据用示例值。循环最多演示 3 次；正式运行才连接真实服务。

定时流程使用星期、时刻和“当天只执行一次”积木，避免每分钟重复开关。当天去重在本次运行中有效；跨重启去重可用“持久保存/读取”模块记录日期。

导出 GitHub Actions

由 GitHub 托管 runner 执行，电脑关机后仍可定时恢复。导出包包含工作流和无 GUI 运行器，不包含个人 Token、房间号或连接凭据。

选择模式后检查兼容性。

导出后按这四步启用

  1. 新建自己的 GitHub 仓库（建议私有），解压 ZIP，把 .github 和 aircon 完整上传到默认分支。
  2. Settings → Secrets and variables → Actions，配置 AIRCON_TOKEN、AIRCON_EXPECTED_ROOM；断点模式还需 AIRCON_STATE_KEY。有连接器时填写 AIRCON_CONNECTIONS_JSON。
  3. Actions → Hall Aircon Cloud → Run workflow，先选 test 模拟，再选 status 只读验证云端连接，最后选 start。定时任务在首次 start 前不会控制空调。
  4. 断点模式用 pause 暂停、resume 继续；reset 清空进度并暂停。进度已加密保存，完整说明位于导出包 CLOUD-README.md。

复制的凭据只应填入 GitHub Secrets。进度密钥会在本机加密保存并复用；已有云端进度时请保持 GitHub 中原有密钥，勿随意替换。Token 到期需重新获取并更新 Secret。

GitHub 单个托管作业最长 6 小时；定时最短 5 分钟，可能延迟、丢弃或因配额停止。断点流程释放等待中的 runner，不提供秒级常驻保障。此按钮只导出文件，不自动上传仓库或执行云端控制。
